# Replay scrubbing vectors

Hand-written cases for the session replay privacy rules. Two implementations
run them and must agree exactly:
- The collector, `@libo11y/rum-replay`, scrubs every rrweb event before it
  is buffered. Its suite is `ts/packages/rum-replay/src/conformance.test.ts`.
- The RUM gateway, `go/o11yrum`, scrubs every segment again before it is
  stored.

The two suites change together. A case that one implementation cannot pass
is a bug in that implementation, or a rule change that both must make.

The `expected` values are written by hand from the rules, never generated by
running a scrubber. The rules are in the file comments of
`ts/packages/rum-replay/src/scrub.ts`, `mask.ts`, `urls.ts`, `css.ts` and
`policy.ts`.

## `mask-text.json`

`{ "cases": [ { "in": "...", "out": "..." } ] }`. Masking replaces every code
point with `*`, except ASCII space, tab, line feed, carriage return, form
feed and vertical tab. Nothing else counts as whitespace: NBSP (U+00A0), NEL
(U+0085), the BOM (U+FEFF), U+2028 and the other Unicode spaces are masked.
One code point gives one `*`, so a combining mark gives its own `*`. A lone
surrogate (JSON `\ud800`) counts as one code point. Go reads it as U+FFFD,
which also masks to one `*`.

## `urls.json`

`{ "allow": [...], "cases": [ { "kind": "url" | "srcset" | "css" | "content", "in": "...", "out": "..." } ] }`.
`allow` is the query parameter allow-list for every case.
- `url` cases strip one URL, as `stripUrl` does. The rules are textual, not
  a URL parser's: a port must not use WHATWG or `net/url` normalization.
- `srcset` cases strip a `srcset` value, as `stripSrcset` does. A candidate's
  URL runs to the next ASCII whitespace, as the HTML parser reads it, so a
  data URL's commas stay inside it.
- `css` cases strip the URLs in a piece of CSS, as `stripCssUrls` does. That
  includes bare URLs in a declaration value, such as a custom property
  (`--bg: https://cdn.example/a.png?token=1`).
- `content` cases strip a kept `content` attribute, as `stripContent` does.
  A value that starts with a URL scheme, `/` or `\` is a URL (`og:url`,
  `og:image`, `twitter:image`) and is stripped like any URL. A refresh value
  (digits, then `;` or `,`) keeps only its delay. Any other value is text.

## `scrub-*.json`

One case per file. Each file has these fields:
- `description` says what the case covers.
- `query_allow_list` is the policy's query parameter allow-list.
- `text_allowed_ids` lists the node IDs whose text and masked attributes the
  client's DOM context allows. It models the client's decision from the live
  DOM: under an unmask selector and under no mask or block selector. Style and
  link elements and the text in them count as allowed, as the DOM context
  allows them, so CSS survives.
- `editable_ids` lists the node IDs the DOM context reports as editable
  content (inside a textarea or a contenteditable element).
- `blocked_ids` lists the node IDs the DOM context reports as under a block
  selector from code or remote configuration. A blocked element keeps only
  `class`, `rr_width` and `rr_height` and no children. Text changes on a
  blocked node and nodes added under a blocked parent are dropped.
- `parent_tags` maps a node ID to the lowercase tag of its parent element,
  for nodes whose parent is not in the event itself: text mutations and the
  root of an added node.
- `secrets` lists strings that must never appear in the scrubbed output of
  any implementation, in either mode below. Each must appear in `events`.
  List every private string a case holds outside `text_allowed_ids`.
- `allowed_texts` lists strings that appear in the output only because of
  `text_allowed_ids`.
- `events` is the rrweb input, in order.
- `expected` is the scrubbed output, in order. Dropped events are absent.
  Objects compare as JSON values: key order does not matter, array order does.

Each scrub case runs in two modes:
- **Trust mode** uses `text_allowed_ids` as given. The output must equal
  `expected`, and no secret may appear in it. The gateway runs this mode for
  an app whose `replay.unmasked_text` is true.
- **Strict mode** uses an empty `text_allowed_ids`. No secret and no
  `allowed_texts` entry may appear in the output. The gateway runs this mode
  by default, so it masks all text whatever the client sent.

The scrubber's context answers five questions about a node ID:
`textAllowed`, `stylesheetAllowed`, `parentTag`, `editable` and `blocked`.
The vectors answer them from the four fields above: `textAllowed` and
`stylesheetAllowed` both from `text_allowed_ids`. Anything not listed is not
allowed, has no known parent tag and is not editable.

The client's DOM context answers `textAllowed` false for a style or link
element itself, so a text attribute on one, or a text change aimed at its own
ID, is masked, and answers `stylesheetAllowed` true for it, so its inlined
stylesheet survives. The vectors model the outcome, not that split.
